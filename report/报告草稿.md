## 1. 问题定义与目标

本项目针对 Amazon 电影评论数据集，构建一条可重复运行的 ETL 流程：从 Stanford SNAP 的历史评论与产品信息中抽取全量数据，识别电影及人物实体，完成清洗、合并与信息补全，将结果装载到数据库，并保证每个最终字段可追溯到原始来源与处理过程。

【待填】最终实际交付的范围边界（全量评论 N 条、产品清单 M 个、电影作品数、人物数——以运行统计为准）。

### 2.2 规模核对

官方统计：评论 7,911,684 条、产品 253,059 个、用户 889,176 个，时间跨度 1997-08 至 2012-10。

**实测解析结果**（`src/stream_review_stats.py` 流式逐行解析，2026-11-03，耗时 66.1 秒）：

| 指标 | 官方数字 | 实测数字 | 结论 |
|------|----------|----------|------|
| 评论条数（records_read） | 7,911,684 | 7,911,684 | ✅ 一致 |
| 不同产品数（distinct ASIN） | 253,059 | 253,059 | ✅ 一致 |
| 不同用户数（distinct userId） | 889,176 | 889,176 | ✅ 一致 |
| 时间范围（reviewTime） | 1997-08 至 2012-10 | 1997-08-20 至 2012-10-25（UTC） | ✅ 一致 |

统计核对账目：**读取记录数 7,911,684 = 有效记录数 7,911,684 + 隔离记录数 0**（校验通过）。
辅助计数：空 userId 记录 0 条；评分超出 1–5 范围 0 条；含编码替换符（U+FFFD）的行 63,567 行（原始文本保留，不影响计数）。
下载完整性：文件 3,321,791,660 字节与 HTTP HEAD 一致；SHA-256 `4b6ee09ea4880f3fb197b1407d45dfb08a892fbb48a9e7a2d74aa0572cdcc715` 已记入 download_meta.json。

解析规则：记录边界为 `product/productId:` 前缀行；字段前缀识别 8 个标准字段；非前缀行视为上一字段续行（兼容 review/text 跨行）；编码异常以 U+FFFD 替换并计数，不中断解析。

**结论**：四项指标全部与官方统计一致，无需进入排查流程。重复记录检查留待任务 8 评论去重阶段专项处理。

【待填】磁盘占用实测：压缩包 3.09 GiB、解压后实际大小（decompress_and_measure.py 输出）、总占用。

### 2.3 磁盘与内存估算（估算依据 + 实测汇总）

估算依据：各分项按"实测单价 × 数量"计算；无法实测的分项标"待填"，由后续运行量出。

| 分项 | 数值 | 来源 |
|------|------|------|
| movies.txt.gz 压缩包 | 3,321,791,660 B（3.09 GiB） | 【实测】HTTP HEAD Content-Length |
| movies.txt 解压文本 | 待填 | 解压后由 decompress_and_measure.py 实测 |
| 产品页面快照 · 单页 | 105,721 B | 【实测】curl 抓取 1 页（ASIN B00006HAXW，2026-11-03） |
| 产品页面快照 · 253,059 页推算 | 26,753,650,539 B（24.92 GiB） | 【样本推算】253,059 × 105,721；实际总量待采集完成后统计 |
| 数据库存储 | 待填 | 装载后 pg_database_size('etl_movie') 实测 |
| 磁盘剩余 | 161.21 GiB / 824.94 GiB 总量 | 【实测】env_check.py（2026-11-03 09:43） |
| 内存峰值 | 待填 | 流式解析设计目标 < 1 GB，以运行观察为准 |

结论【实操建议】：快照是最大分项（单页约 103 KB，全量推算近 25 GiB）。应对：① 快照 gzip 压缩存储（原始响应可解压还原，符合"保留原始证据"）；② 采集清单等元数据入数据库不占文件空间。按 gz 3.09 GiB + 解压 6~9 GiB + 快照 25 GiB（压缩后预计 5~8 GiB）+ 数据库 5~10 GiB 估算，预留 **40 GiB** 较稳妥【样本推算，非实测总量】。

### 4.2 产品页面采集

【待填】ASIN 去重数量、采集清单字段、Scrapy 配置（限速/并发/重试/robots.txt）、采集状态分布表（成功/页面不存在/访问受限/超时/解析失败/未采集，互斥状态数之和 = ASIN 总数）、失败原因与证据保留方式、HTTP 200 验证页判别规则。

**采集合规准备（已实测，2026-11-03）**：

1. **robots.txt 实测分析**（https://www.amazon.com/robots.txt，7,947 字节）：`User-agent: *` 组**未禁止** `/dp/<ASIN>` 商品主页（程序化验证 `can_fetch=True`）；仅禁止交互子路径 `/dp/shipping/`、`/dp/rate-this-item/`、`/dp/e-mail-friend/` 等 6 条；未声明 Crawl-delay。`/product-reviews/` 默认允许（个别 ASIN 除外）。
2. **合规配置**（`src/crawler/amazon_crawler/settings.py`，已加载验证）：`ROBOTSTXT_OBEY=True`；DOWNLOAD_DELAY=2.0（随机抖动）；CONCURRENT_REQUESTS_PER_DOMAIN=2；AutoThrottle 目标并发 1.0、最大延迟 60s；RETRY_TIMES=3（408/429/5xx）；HTTPCACHE 开启（断点续跑配套缓存）；可识别 USER_AGENT；Cookies 关闭。
3. **红线**（作业明确要求）：遇到访问限制不得绕过验证、登录或封禁；受限/失败一律记录状态与证据，不伪造成功。
4. **Spider 骨架**：`src/crawler/.../spiders/product_spider.py`（ASIN 清单 → /dp/ 请求 → 产出含 content_sha256 的采集清单条目）。

**小批量试采（20 ASIN，2026-11-03 实测）**：

| 状态（互斥） | 数量 | 证据 |
|--------------|------|------|
| 成功 | 1（B0070225F4） | 快照 136,998 B gzip，含 productTitle 等商品页特征 |
| 访问受限 | 18 | 快照均为 3,781 B 原始 HTML 验证页（含 captcha 特征），逐个留档 `snapshots/pages/`，**未标记为成功** |
| 抓取失败 | 1（B007NF02Q2） | HttpError（无响应体，无快照），已记入清单 |
| 合计 | 20 | = ASIN 试采清单数，校验通过 |

处置过程：首采 18 个受限后，按"自行调整爬虫程序"要求降速重试（DOWNLOAD_DELAY 10s、单并发）——仍受限，且 curl 同样返回验证页（3,781 B），判定为站点反爬对本出口 IP 的验证拦截。遵守"不得绕过验证/登录/封禁"红线，保留全部验证页快照作为访问受限证据，不伪造成功。

快照索引：`snapshots/index.csv`（20 行，含 requested_url、final_url、http_status、processing_status、content_sha256、content_length、snapshot_path、fetched_at_utc、attempts）。
快照完整性抽检（seed=42 随机 2 个）：B00004CQT4、0790747324 重算 SHA-256 与索引**全部 MATCH**（解压后重算，与 content_sha256 字段一致）。

【待填】全量采集策略调整（错峰/长间隔渐进采集；失败 ASIN 保留未采集状态供后续批次重试；替代数据源范围与完整性说明）。

## 7. 缺失信息补全与冲突处理

### 7.1 上映信息补全（任务6）

上映时间语义分层：作品首映/上映年份（`release_year`，precision=year）、指定地区上映日期（IMDb 基础表不提供，预期 NULL）、商品发售日期（存 edition 域，**永不充当上映日**）。补全主源 = IMDb title.basics.startYear（实测 movie 覆盖 647,293/759,812 = 85.2%，YYYY 精度）；辅助源 = IMDb title.principals/crew 用于作品匹配验证。匹配流程：标题标准化 → tconst 候选 → 年份±1/导演/类型联合验证 → 未匹配标 `no_imdb_match`。

【待填】补全运行记录：每次补全的来源、原始值、抽取时间、匹配证据、选择规则、置信度（FieldAssertion 实际行数据）。

精度标记实现：仅知年份时存 `release_year` + `precision=year`，**禁止补成 1 月 1 日**；完整上映日期字段大量 NULL，原因 `imdb_provides_year_only`（实测边界：IMDb 公开基础表只有年份）。earliest_review_time 仅作参考；条件性上界另存 `inferred_release_bound` + 推断条件 + confidence + status=inferred，不覆盖已核实值。详见 `report/数据源策略.md` 与 `report/字段覆盖矩阵.md`。
