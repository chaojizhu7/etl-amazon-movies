# 项目报告 · 定稿（Amazon 电影评论与多源电影信息集成）

> 数据存储与管理 ETL 作业 · 单人完成 · etl=v1.0 · 2026-11-06
> 仓库：https://github.com/chaojizhu7/etl-amazon-movies
> 所有数字来自 `logs/summary/` 实测输出与 `report/人工复核记录.md`；AI 产出不作为事实来源（见 `ai_usage/AI使用记录汇总.md`）。

## 1. 问题定义（作业 p1 首页要求）

从 Stanford SNAP `movies.txt.gz`（791 万条 Amazon 电影评论）与 253,059 个产品出发，构建一条可重复运行的 ETL 流程：识别电影/人物实体，完成评论清洗、实体合并与多源信息补全，装载 PostgreSQL，且**每个最终字段可追溯到原始记录**。验收关注三点：数据正确、合并有依据、结果可追溯。

核心建模约束（作业红线）：ASIN（商品版本 edition）≠ movie_id（创作作品）；上映日期 ≠ 商品发售日期 ≠ 最早评论时间；合集评论归商品不拆分；原始评论全保留（逻辑评论用映射关联）；同名≠同一人。

## 4. 架构（作业 p6 八）

**Airflow 2.10.4（WSL Ubuntu 24.04）编排 + Scrapy/Python 抽取转换 + PostgreSQL 17.11 装载**（课程 PPT 开源工具清单内选型，弃 Spark/Beam 等——单机数据量足够、无 CDC、需规则版本表达）。

DAG 八步链（`etl/dags/movie_etl_dag.py`，run_id/规则版本参数化）：
```
extract → crawl → classify → merge → enrich → dedup → lineage → quality_check
```
- 每 task 输入/输出/依赖明确；失败写 `quality_issue`（4 类：task_failed/check_violation/fk_orphan/count_mismatch），on_failure 告警，重试上限内自动补跑；
- **幂等**：UPSERT + run_id 记录 + 派生表全量重建（review_mapping 有序 INSERT+索引管理）；`--resume` 跳过已成功 task（QA-3 测试二实证 7 SKIP）；
- 中断恢复：失败/被杀 task 单独补跑不漏不重（QA-3 测试二：两次强杀零残留、续跑恰一次完整产出）；
- 规则版本变化：决策表按 run_id+rules_version 双标签留史，可定位影响范围并回滚（QA-3 测试三）。
- **四层处理**（p6 要求）：原始层（评论文件+页面快照+IMDb tsv）→ 暂存层（结构化抽取值+异常记录：release_facts/field_assertion/review_anomaly）→ 集成层（movie_entity/person_entity/product_movie/movie_person）→ 目标层（查询视图：sql/queries/ 五查询）。
- ER 图与建表脚本：`sql/01..10_*.sql`（键/约束/索引/字段字典见 `sql/README`）；软外键设计（DROP movie_id/person_id FK，一致性交 quality_check.fk_orphan——重算不被 FK 锁死）。

## 5. 实体及日期语义（作业 p3 五 / p5 任务6）

- **movie_id**（作品）：系统生成稳定 ID（成员集签名复用，重跑不换号）；保留全部 ASIN→作品映射（product_movie 多对多：合集成员关系 relation_type='collection_member'）。
- **edition_id = ASIN**（商品版本）：不随作品合并而删除；载体/语言/剪辑版等版本属性存产品页原文（page_title_raw）+解析标签（查询①）。
- **person_id**：系统生成（不用姓名/nconst 充当）；同名≠同一人（缩写兼容 T=0.5 封顶 manual；年代硬冲突=间隙>5 年且双方各≥5 部已知作品）；movie_person 表达角色（director/actor/actress），同一人多角色多行。
- **上映时间三层语义**（p5：不同语义日期不能直接择优比较）：
  1. 作品首映/上映年份 → `release_facts.fact_type='release_year'`（source=imdb.startYear，**precision='year'，仅出 YYYY 不补 1 月 1 日**）；
  2. 柰地区上映时间 → `regional_release_date`（有来源再记录，本数据集产品页无此信息=缺失留 NULL+missing_reason）；
  3. 商品发售日期 → `edition_sale_date`（产品页语义，**永不写入 release_date**）。
- 精度标记：precision ∈ {year, day, none}；推断值 status=inferred + confidence + 依据（earliest_review_time 只作 `earliest_review_time`，条件上界另存 `inferred_release_bound`）；缺失= NULL+missing_reason 词表（10 个原因码，见 sql/queries/q3）。

## 6. 合并及选择规则（作业 p4 任务4 / p5 任务7）

**merge_rules v1.3**（`rules/merge_rules_v1.md`，用户审核定稿）：
- 6 信号验证：title / year / director / cast / runtime / genre；V=加权验证分（0~1）；
- auto_merge 门槛：T≥0.85 且 V≥0.65 且 强信号≥2 且 known≥3；hard 冲突直判 no_merge（续集序数/导演异+主演零重合/片长比>1.6）；
- S1 title_conflict 且 V≥0.80 → manual_review（别名同片人工判，如 Scrooge≡A Christmas Carol 1951、Dracula≡Bram Stoker's Dracula 1992）；V<0.80 维持 no_merge；
- 多候选未消歧节点不进 auto（`ambiguous_node_ceiling`→manual，防并集污染）；链一致性 clique 检查防传递性误并；
- 人工裁定优先：decision='manual_merge'/'no_merge'，reason='manual_confirm: …'，来源=人工，追加不改历史。

**field_selection_rules v1.0**（`rules/field_selection_rules_v1.md`）：R1 语义边界 → R2 匹配可靠性（resolved_tconst>唯一候选>全体一致）→ R3 来源权威（作品级 imdb>product_page、edition 级 product_page 唯一）→ R4 语义一致 → R5 日期精度 → R6 采集时间仅平局 → R7 人工判定继承；**禁"最后抓到/多数票"裸理由**；全候选保留，rejected 必附词表理由，conflict 不编造。

**5+5 实例（附证据，详见 logs/summary/merge_eval_sample.csv 与人工复核记录）**：
合并：① Scrooge≡A Christmas Carol 1951（4 对，V=0.93~1.00 演职员/年份/片长全合，短名发行别名）② Dracula≡Bram Stoker's Dracula 1992（title 冲突但 Coppola/Oldman 同署名）③ Robin Hood 2010 双剪辑合装（140+156=296≈297min 核算，B002ZG98VE 标 inferred dual_cut_bundle）④ Notebook≡El diario de Noa（西语原名）⑤ Das Boot 六版本（含 Director's Cut）。
不合并：① Iron Man×Iron Man 2（续集序数硬冲突，六信号合仍拦）② Puss in Boots 正片 vs 短片 Three Diablos ③ Metropolis 1927 vs 同名异片（共享 tconst≠同片）④ Wachowski 姐妹（Lilly×Lana，共享 3 部 Matrix 作品仍拦）⑤ Trevor×Terrence Howard（互斥代表作+deathYear 矛盾）。

### 7.4 预售、合集和跨版本评论（单独讨论，作业 p4-5 评论归属语义）

- **预售**：本数据集最早评论 1997-08-20，无预售期（先于发行）评论数据；若出现 `earliest_review_time < release_year` 的产品，系统以 `inferred_release_bound` 存条件上界并标 inferred，不反推发行日期（实测该类 0 件）。
- **合集评论**：合集 ASIN 的评论**归商品，不拆分/不复制**给成员电影（ProductMovie 多对多映射：B00198X0UO 等合集成员只挂 collection_member 关系，其评论统计留在合集 ASIN；查询⑤ 口径 1）。合集商品分类独立（classification='collection' 10 行），不冒充单一作品。
- **跨版本评论**：同一用户在不同 edition 上的相似评论**全部保留不删**（仅统计）：相似组 **1,239,387 组 / 7,240,056 条**（任务8 评论清洗实测）；删除的仅是"同一 ASIN+用户+时间+评分+文本"完全相同的重复副本 **5,146** 条（逻辑评论 7,906,538）；评分口径：版本合并分母=逻辑评论数（不含副本），helpfulness 只校验不加权（异常 43 项留 review_anomaly）。
