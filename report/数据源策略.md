# 多源数据补全策略文档

> 配套作业：任务2（产品页面采集）/ 任务6（补全上映信息）/ 任务7（来源冲突处理）
> 原则：**替代源数据永不冒充产品页数据**；每个字段携带来源标签；缺失如实标 NULL + 原因。

---

## 0. 试采结论回顾（2026-11-03 实测）

20 ASIN 试采：成功 1 / 访问受限 18（验证页快照留证）/ 抓取失败 1。受限页为 3,781 B captcha 验证页，降速重试无效，curl 交叉验证同样受限 → 判定为站点反爬对出口 IP 的验证拦截。据此设计以下"实时采集保底 + 离线补全"双轨策略。

## 1. 实时采集策略（优先保底）

### 1.1 采集排期（错峰长间隔渐进）

| 参数 | 值 | 依据 |
|------|-----|------|
| 每日采集量 | 300 ASIN（3 波 × 100） | 作业建议"每天几百个" |
| 波内请求间隔 | 30s（随机抖动 ±10s） | 远宽于试采的 2s，降低触发阈值 |
| 波间间隔 | ≥ 4 小时 | 错峰 |
| 采集时段 | 避开整点，随机分钟启动 | 分散负载 |
| 单日运行时长 | 约 50 分钟/波 | 100 × 30s |

### 1.2 优先级队列

1. **Top-Review ASIN 优先**：按评论数降序（覆盖绝大多数评论的头部产品）
2. 合集/多电影产品标记后人工复核队列
3. 尾部 ASIN 最后（长尾产品元数据缺口可由 IMDb 兜底）

### 1.3 失败处置与重试

- 失败 ASIN **保留 `access_restricted` / `fetch_failed` 状态**，不删除、不改判
- 重试节奏：T+1 日首次重试 → T+3 二次 → T+7 三次，三次仍失败转 `permanently_unreachable`（保留全部证据）
- 每次重试追加 `attempts`、`fetched_at_utc`、批次号（run_id），清单保留历史记录
- HTTP 200 验证页判别规则继续生效：**永不标记为成功**

### 1.4 合规红线（作业明确要求）

- robots.txt 遵守（已实测 /dp/ 允许、交互子路径禁止）
- 不绕过验证、不登录、不破封禁
- 受限证据 = 验证页快照（已留档 `snapshots/pages/`）

## 2. 离线 IMDb 补全策略

### 2.1 数据集范围（2026-11-03 实测下载 + 全量扫描）

| 文件 | 字节数 | 行数 | 用途 |
|------|--------|------|------|
| title.basics.tsv.gz | 229,636,410 | 12,921,360 | 作品标识 tconst、primaryTitle/originalTitle、startYear、genres、titleType |
| title.crew.tsv.gz | 83,877,657 | 12,918,857 | directors/writers（nconst 数组） |
| name.basics.tsv.gz | 312,306,248 | 15,783,070 | 人物 primaryName、生卒年、职业 |
| title.principals.tsv.gz | 789,511,688 | 102,659,089 | 主创名单（含 ordering、category、characters） |
| title.ratings.tsv.gz | 8,732,618 | 1,728,260 | IMDb 评分（辅助参考，非亚马逊评分） |

未下载（暂列后续批次）：title.akas.tsv.gz（496.5 MB，别名/地区译名，用于标题匹配增强）。

### 2.2 字段级使用边界【范围声明，作业红线】

| IMDb 字段 | 可支持 | **不可宣称** |
|-----------|--------|--------------|
| startYear | **上映年份**（647,293 / 759,812 部 movie 有值 = **85.2%**） | **完整上映日期**（无月日、无地区分层上映日）——缺失一律 precision=year |
| genres | 类型标签（≤3 个/片） | 全部类型、受控词表映射（需自建映射规则） |
| title.crew.directors | 导演 nconst 列表（7,157,755 / 12,918,857 条有值 = **55.4%**） | 无导演值条目的导演信息 |
| title.principals | **主要**演职员（actor/actress 行 4,258 万 + director 行 866 万，含排序） | **全部演员**（仅 principals，非完整 cast）；主角判定需自定义规则 |
| name.basics | 人物规范名、职业、参演作品线索 | 人物身份确认本身（需与署名联合消歧） |

**来源冲突规则**：IMDb 与产品页同字段不一致时，按任务 7 选择规则逐字段裁决（语义/权威性/精度），候选值全部保留；**IMDb 值的来源标签永远是 `imdb`，绝不写成 `product_page`**。

### 2.3 匹配流程（IMDb ↔ 电影作品）

1. 标准化标题（大小写、标点、语言别名）→ 生成候选 tconst
2. 验证特征联合确认：上映年份（±1 容差）、导演 nconst 重合、类型重合
3. 仅标题相似**不足以**合并；置信度 + 证据写入 MergeDecision / FieldAssertion
4. 未匹配成功的电影保留 NULL + `missing_reason=no_imdb_match`

## 3. 实时采集与离线补全的分工矩阵

| 数据域 | 主源 | 备注 |
|--------|------|------|
| 评论内容（文本/评分/时间/用户） | SNAP 评论文件（已全量核对 MATCH） | 无缺口 |
| 商品版本信息（载体/字幕/地区码/发行商/发售日） | 产品页（实时采集） | IMDb 无此域；缺口 = NULL + missing_reason=page_unreachable |
| 作品上映年份 | IMDb startYear（85.2% movie 覆盖） | 产品页发售日**不得**充当上映日 |
| 作品标题 | 产品页 + IMDb 双源 | 冲突走选择规则 |
| 类型 | IMDb genres + 产品页 | 并集，逐成员标来源 |
| 导演/主演 | IMDb crew/principals + 产品页 | principals 仅主要演职员 |

## 4. 替代数据完整性总声明【报告必载】

1. IMDb 数据集为**非商业许可**（IMDb Non-Commercial Datasets），仅课程作业范围内使用，提交物只放校验值、样本与匹配结果，不转发原始全集。
2. IMDb 数据**每日刷新**，本项目锁定 2026-11-03 下载批次；批次指纹已固化：`data/raw/imdb/checksums.sha256`（5 文件逐一 SHA-256）与 `data/raw/imdb/download_meta.json`（URL/字节数/哈希/下载时间），复现须用同批次文件并先校验哈希。
3. 覆盖缺口（实测）：15.8% 的 movie 无 startYear；44.6% 的 crew 行无 directors；principals 非完整 cast。缺口字段一律 NULL + missing_reason，**不用推断值冒充实测值**。
4. 任何来自 IMDb 的字段值在血缘中记 `source=imdb` + tconst/nconst 定位；来自产品页的记 `source=product_page` + URL/快照哈希；**两类来源在查询接口中可分离统计**。
